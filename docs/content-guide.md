# 問題データ執筆ガイド

知識カードと問題（ADR-0008）を書くときの基準。人が書くときも、LLM で生成するときも、このガイドに従う。

## 基本の考え方

- 事実（何が・いつ・どこで・誰が）だけでなく、**なぜ**（目的・背景・原因）と**その結果**（影響）を結びつけて覚えられるようにする。理由と結びついた知識は忘れにくい
- 読んだ人に**答えのない疑問を残さない**。疑問を呼ぶ情報を書くなら、その答えも書く
- 確かめられないことは書かない。すべての知識カードに出典を付ける

## サブカテゴリの立て方

- **一つの問いで貫く**: 「江戸時代」のような区切りではなく、「日本の宗教はどう移り変わったか」「江戸の庶民はどう暮らしていたか」のように、答えを知りたくなる問いを立てる。問いは `_theme.json` の `description` に書く
- **広く始めて、増えたら切り出す**: 問題が少ないうちは広いサブカテゴリで始める。知識カードが 40 枚を超えるか、中身がばらけてきたら、狭いサブカテゴリを切り出す。切り出しても知識カードと問題の ID は変えない
- **知識カードの置き場所は 1 つ**: 複数のサブカテゴリに関わる知識は、その「なぜ」が最も中心になるサブカテゴリに置き、ほかとは `links` で結ぶ
- **解放順（`unlockOrder`）**: 問いへの答えが順に見えてくるように並べる。多くの場合は年代順が自然

## 知識カードの各項目

| 項目 | 答える問い | 書き方 |
|---|---|---|
| `title` | 何か | 短い名詞句。教科書で一般的な呼び方にする |
| `summary` | 何が・いつ・どこで・誰が | 1〜2 文。事実だけを書く |
| `why` | なぜ | 目的・背景・原因を 1〜2 文。制度や政策は**意図**を書く |
| `links` | その結果どうなったか／ほかの知識との関係 | 軸（時代・地理・因果・人物・比較）ごとに 1 文。こじつけになるなら作らない |
| `trivia` | へぇ | 下の基準を満たすものがあるときだけ 1 文 |

### `why` の書き方

- **意図と結果を区別する。** 制度や政策は「何のために作られたか（意図）」と「実際に何が起きたか（結果）」が混同されやすい。`why` には意図を書き、結果は `links`（因果）か `trivia` に書く
  - 例（参勤交代）: 意図 = 将軍と大名の主従関係を確かめる奉公（軍役）を制度にした。結果 = 大名の財政負担が大きくなり、街道や宿場町が発達した
- 作品の場合は、なぜその主題・表現で描かれたか（注文の経緯、時代の要請、画家のねらい）を書く
- 定まった説明がない場合は `why` を書かないか、「〜という解釈がある」と明示する

## 確からしさの表現

| 状況 | 表現 |
|---|---|
| 定説 | 言い切る（「〜した」） |
| 有力だが確定ではない | 「〜とされる」「〜と考えられている」 |
| 議論がある・複数の説がある | 「〜という説もある」「諸説ある」。主な説を併記する |
| 俗説・よくある誤解 | 「〜と説明されることも多いが、〜」の形で正す |

- 議論のある内容を、択一問題の**誤答にしない**（誤りと断定することになるため）。解説で触れるにとどめる

## 「へぇ」（`trivia`）の基準

載せるものの優先順位:

1. **よくある誤解を正すもの**（例:「夜警」は実は昼の場面を描いたとされる）
2. **意外な因果**（例: 出島はもともとポルトガル人のために築かれた）
3. **名前の由来**
4. **印象に残る数字**（規模・年齢など）

載せないもの:

- 読んだ人に疑問を残したまま終わるもの（例:「参勤交代は藩の財政を圧迫した」だけでは、それが目的だったのかという疑問が残る）
- 本題と関係の薄い雑学
- 出典で確認できないもの

## 問題の書き方

- **出題形式は内容で選ぶ**（ADR-0008）: 年代の前後関係 → 並べ替え、作品 → 画像付き択一、場所 → 地図、人物と出来事 → 組み合わせ、時代・様式の区別 → 分類
- **「なぜ」も問う。** 事実の暗記だけでなく、目的や原因を問う択一を作る（例:「参勤交代が制度化された主なねらいは？」）
- **誤答の選択肢**は、紛らわしいが明確に誤りであるものにする。結果や副作用を「目的」の誤答にするのは、区別を学べるので有効
- **解説（`explanation`）**は、なぜその答えになるかを 2〜3 文で書く。紛らわしい誤答がある場合は、それが違う理由も書く
- 問題文は、それだけで答えが一つに決まるように書く。地図問題は「現在の都道府県で」のように基準を明記する
- ○×問題は作らない。「誤っているものを選べ」の択一にする

### 部分指定（マーカー）の使い方

マーカーの座標は画像を見ないと正しく置けず、ずれやすい。次の決まりを守る。

- **対象を絞る**: 人物・動物・建物の部位など、大きくてはっきり区別できるものに限る。小さな細部（手に持った小物など）には使わない
- **数と間隔**: マーカーは 3〜4 個まで。互いに離して置く（近すぎると `pnpm validate` がエラーにする）
- **確認は必須**: `pnpm check:markers` で描画した画像を見て、すべてのマーカーが意図した対象の上にあることを確認してから、`pnpm check:markers --approve <問題ID>` で確認の記録を残す。画像やマーカーを変えると記録が無効になり、`pnpm validate` がエラーにする
- **細部を問いたいときは文章で問う**: 「奥の壁の鏡に映っているのは誰？」のように位置を問題文で説明し、選択肢は文字にする。座標を使わないのでずれない

## 表記

- 年は西暦で書く。和暦を併記する場合は「1635年（寛永12年）」
- 人名は、その知識カードで初めて出るときはフルネーム（例: 徳川家光）
- 外国の人名・作品名は日本の教科書・美術館で一般的な表記にする

## 出典

- `sources` には、内容を確認した資料を書く（教科書・事典・美術館の公式解説など）
- 学説の状況（意図か結果か、定説か異説か）を書くときは、特に出典で確認する

## チェックリスト

- [ ] `summary` は事実だけで、1〜2 文に収まっている
- [ ] 制度・政策・作品には、分かる範囲で `why` がある。意図と結果が混ざっていない
- [ ] `trivia` は基準を満たし、答えのない疑問を残さない
- [ ] 確からしさに応じた表現になっている
- [ ] 議論のある内容を誤答にしていない
- [ ] `pnpm validate` が通る（マーカーは画像を見て確認し、`--approve` で記録済み）
