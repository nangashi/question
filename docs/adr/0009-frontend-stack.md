# 0009. フロントエンドは Vite + Preact + TypeScript、パッケージ管理は pnpm

- ステータス: 承認（実装済み）
- 日付: 2026-09-25
- 関連: ADR-0001, ADR-0003, ADR-0005, ADR-0008

## 背景

スマホで使う PWA を作る。問題データは静的 JSON（ADR-0001）で、配信は Cloudflare Workers の静的アセット（ADR-0005）。画面数は多くなく、主な処理は出題・採点・進捗表示と端末内の保存（ADR-0003）。まずモック画面で UX を確認し、その実装を本番の土台にしたい。

## 決定

- ビルド: Vite
- UI: Preact（React 互換の API で軽量）
- 言語: TypeScript（strict）
- パッケージ管理: pnpm
- データ検証: zod。問題データ（ADR-0008）のスキーマを TypeScript の型と共有し、開発時とビルド時に `content/` を検証する
- テスト: Vitest（採点ロジック・スキーマ検証など）
- 問題データと画像は `content/` に置き、Vite の `import.meta.glob` で読み込む
- 画面遷移はハッシュルーティング（静的配信で追加設定が不要）
- スマホ実機での確認は、同じ LAN から開発サーバー（`vite --host`）に接続して行う

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **Vite + Preact（採用）** | 軽量でスマホ向き。React の知識と部品を流用できる | React 専用ライブラリの一部は互換レイヤーが必要 |
| Vite + React | エコシステムが最大 | バンドルがやや大きい |
| Svelte / SvelteKit | 軽量で記述が簡潔 | React 系の知識を流用できない |
| Next.js などのフルスタック FW | 機能が豊富 | 静的 PWA には過剰。Workers との組み合わせが複雑 |

## 結果

- 良い影響: 小さなバンドルでスマホでも軽い。静的配信のまま Workers に載せられる
- 悪い影響: ルーティングや状態管理は最小限を自前で用意する
- リスク: 将来 React 専用ライブラリが必要になった場合 → `preact/compat` で対応する
