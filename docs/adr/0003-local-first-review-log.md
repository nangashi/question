# 0003. 学習記録は解答ログとして端末の IndexedDB に追記し、サーバーは同期先とする

- ステータス: 承認（一部実装済み: 端末内の保存と書き出し・読み込み。サーバーとの同期は未実装）
- 日付: 2026-09-25
- 関連: ADR-0002, ADR-0005, ADR-0007

## 背景

進捗は利用者ごとに保存したい。API（ADR-0005）を用意するが、ログインは任意（ADR-0007、提案中）とする方針のため、未ログインの利用者の保存先が必要。スマホでは電車内などのオフライン利用も想定される。

## 決定

- 学習記録はローカルファーストとし、端末の IndexedDB に保存する。サーバーは同期先として扱う
- 保存するのは「いつ・どの問題に・どう答えたか」の**解答ログ（追記のみ）**。FSRS の状態はログから再計算できる派生データとする
- 同期時は端末とサーバーのログを和集合でマージし、FSRS の状態を再計算する。これにより複数端末での学習でも矛盾が生じない
- `navigator.storage.persist()` で永続化を要求し、PWA としてホーム画面への追加を促す
- 学習記録の JSON エクスポート / インポートを提供する（未ログイン時の唯一のバックアップ手段）
- 出題中の状態（出題する問題の並び・何問目か・回答・結果）は、解答ログとは別に localStorage へ一時保存する。出題ごとに ID を発行して URL に含め、戻る操作や再読み込みで同じ URL に戻ったときに続きから再開する。保存は直近 5 件まで。localStorage が使えない環境では保存せずに動く

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **IndexedDB + 解答ログ（採用）** | 容量に余裕がある。非同期で UI を止めない。マージしやすい | API がやや煩雑 → ラッパー（`idb` や Dexie）で吸収する |
| localStorage | 実装が最も簡単 | 約 5MB の上限。同期 API で UI を止める。ログが増えると破綻する |
| サーバーのみに保存（ログイン必須） | 端末側がシンプル | ログインが必須になる。オフラインで使えない |
| FSRS の状態だけを保存 | データが小さい | 端末間のマージで競合する。再計算できない |

## 結果

- 良い影響: ログインなし・オフラインで動く。同期を後から追加できる
- 悪い影響: ログが増え続ける → 必要になったら古いログを状態のスナップショットに圧縮する
- リスク: iOS Safari では、PWA でないサイトは 7 日間使わないとデータが消えることがある → PWA 化、`persist()`、エクスポート、ログイン同期（ADR-0007）で緩和する
