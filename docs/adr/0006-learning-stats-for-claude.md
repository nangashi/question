# 0006. 学習データを要約して Claude に連携し、定期実行で問題を改善する

- ステータス: 承認（未実装）
- 日付: 2026-09-25
- 関連: ADR-0001, ADR-0002, ADR-0005, ADR-0007

## 背景

回答率やよく学習しているテーマなどを Claude に渡し、苦手分野の問題追加や、誤りのある問題の修正に活かしたい。問題は事前生成（ADR-0001）なので、学習データ → Claude → 問題更新 → デプロイのループを作る必要がある。

## 決定

- 学習データを LLM 向けに要約した「Claude 用レポート」の形式を定義する。手動エクスポートと API（ADR-0005）の両方で同じ形式を使う
- レポートに含める内容:
  - テーマ単位: 学習回数・学習時間・学習済み / 定着済み / 未学習の問題数・最終学習日
  - 問題単位: 解いた回数・正答率・FSRS の難易度・よく選ばれる誤答・報告フラグ
  - 傾向: よく開くテーマ・サブカテゴリ・途中離脱・苦手なタグ
- 段階的に導入する:
  1. アプリに「Claude 用レポート」のコピー / ダウンロード機能を付け、手動で Claude Code に渡す
  2. API から取得できるようにし、定期実行エージェント（`/schedule`）が週次で「データ取得 → 問題の追加・修正 → PR 作成」を行う。PR はスマホの GitHub アプリからマージする
  3. 必要になったら、同じ Worker を MCP サーバー化し、Claude アプリから直接問い合わせられるようにする
- 認証（ADR-0007）が決まるまでは、開発者本人が秘密キー付きで送信したデータだけを集計対象とする。他の利用者の匿名データは送信・集計しない

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **要約レポート + API + 定期実行（採用）** | スマホだけでループが完結する。データ量が小さい | Worker とエージェントの設定が必要 |
| 手動エクスポートのみ | インフラが不要 | 自動化できない |
| 生の解答ログをそのまま渡す | 情報を失わない | トークン量が多く、集計を毎回 Claude が行う必要がある |

## 結果

- 良い影響: 苦手分野に合わせて問題を追加でき、問題の品質（正答率が極端に低い・報告が多い）を継続的に改善できる
- 悪い影響: 当面は開発者本人のデータしか使えず、問題の品質評価の母数が少ない
- リスク: 自動生成の PR に誤りが混入する → PR レビューを必須とし、ADR-0001 の検証パスを定期実行にも適用する
