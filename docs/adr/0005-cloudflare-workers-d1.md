# 0005. Cloudflare Workers（静的配信 + Hono API）と D1 で構成する

- ステータス: 承認（未実装）
- 日付: 2026-09-25
- 関連: ADR-0003, ADR-0006, ADR-0007

## 背景

アプリを無料で公開したい。また、学習データを Claude に連携する自動化（ADR-0006）や、将来の端末間同期（ADR-0007）のために API が必要になる。

## 決定

- アプリ（PWA）の静的配信と API を 1 つの Cloudflare Workers プロジェクト（Workers Static Assets + Hono）にまとめ、1 回でデプロイする
- データは D1（SQLite）に保存する。KV は書き込み枠が小さいため使わない
- 無料枠に収めるため、送信は 1 問ごとではなく 1 回の学習ごとにまとめる。サーバー側は日ごと・問題ごとの集計行を更新し、集計済みのデータを返せるようにする
- 送信に失敗した分は端末（ADR-0003）に残し、次回まとめて送る
- 書き込み API には、スキーマ検証・サイズ制限・ID ごとのレート制限をかける
- 読み取り API（Claude・定期実行エージェント用）は、Worker のシークレットに登録した Bearer トークンで保護する

想定するエンドポイント:

| エンドポイント | 用途 | 保護 |
|---|---|---|
| `POST /sessions` | 1 回の学習の要約を受け取る | スキーマ検証・サイズ制限・レート制限 |
| `GET /stats/me` | 自分用の苦手分析 | Bearer トークン |
| `GET /stats/questions` | 問題ごとの集計（品質確認用） | Bearer トークン |

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **Cloudflare Workers + D1（採用）** | 無料枠が十分。配信と API を同一オリジンにでき、CORS が不要 | Workers の CPU 時間制限（無料で 10ms / リクエスト） |
| GitHub に直接保存（Gist など） | サーバー不要 | 本人以外のデータを扱えない。集計を毎回 Claude が行う必要がある |
| GitHub Pages + 別の BaaS（Supabase など） | 機能が豊富 | 依存するサービスが増える |

## 結果

- 良い影響: 無料で運用できる。無料プランは上限超過時に課金されずエラーになるため、想定外の請求が発生しない
- 悪い影響: 認証（ADR-0007）が入るまでは、書き込み API を誰でも呼べる → 集計は参考値として扱い、自分のデータは ID で絞り込む
- リスク: 定期実行エージェントの実行環境から Worker のドメインに届かない可能性 → 環境のネットワーク許可設定で対応する

## 未解決事項

- 無料枠の最新値を Cloudflare の公式料金ページで確認する（Workers のリクエスト数・CPU 時間、D1 の容量・読み書き行数）
