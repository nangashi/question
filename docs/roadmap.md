# ロードマップ

## 運用ルール

- このファイルがタスクと進捗の唯一の正本。各フェーズのタスクをチェックボックスで管理する
- 設計上の決定はここに書かず ADR（`docs/adr/`）に記録し、番号で参照する
- GitHub Issues を導入する場合は、タスクを Issue に**移し**、このファイルからチェックボックスを削除する（併用しない）。その後このファイルはフェーズの目的・範囲・完了条件だけを持ち、各フェーズを Milestone に対応させる

## Phase 1: MVP

- 目的: 自分が毎日使い続けられるかを検証する
- 範囲: 2 テーマ（各 2〜3 サブカテゴリ × 10〜15 問程度）、全出題形式（択一・並べ替え・組み合わせ・分類・年代推定・地図・部分指定）+ 解説・つながり、FSRS による復習、IndexedDB への保存、PWA、エクスポート / インポート
- 範囲外: API、ゲーム要素
- 関連 ADR: 0001, 0002, 0003, 0004, 0008
- 完了条件: 自分のスマホで 1 週間続けて使えた

進め方: C（問題の質を確かめる）→ A（ローカルで学習の仕組みと UX を確かめる）→ B（実環境へデプロイ）

## Phase 2: API と Claude 連携

- 目的: 学習データをもとに、問題の追加・修正のループを回す
- 範囲: Claude 用レポート（手動）→ Cloudflare Workers + D1 の API → 定期実行エージェントによる PR 作成
- 関連 ADR: 0005, 0006
- 完了条件: 定期実行が作った問題追加・修正の PR をスマホからマージできた

- [ ] Claude 用レポートの形式を定義し、コピー / ダウンロード機能を付ける
- [ ] Cloudflare の無料枠の最新値を確認する
- [ ] Workers（静的配信 + Hono API）と D1 を構築する
- [ ] 学習データの送信（学習 1 回ごとにまとめて送信、失敗時は次回再送）
- [ ] 集計と読み取り API（Bearer トークンで保護）
- [ ] 定期実行エージェントを設定する（`/schedule`）
