# ロードマップ

## 運用ルール

- このファイルがタスクと進捗の唯一の正本。各フェーズのタスクをチェックボックスで管理する
- 設計上の決定はここに書かず ADR（`docs/adr/`）に記録し、番号で参照する
- GitHub Issues を導入する場合は、タスクを Issue に**移し**、このファイルからチェックボックスを削除する（併用しない）。その後このファイルはフェーズの目的・範囲・完了条件だけを持ち、各フェーズを Milestone に対応させる

## Phase 1: MVP

- 目的: 自分が毎日使い続けられるかを検証する
- 範囲: 2 テーマ（各 2〜3 サブカテゴリ × 10〜15 問程度）、全出題形式（択一・並べ替え・組み合わせ・分類・年代推定・地図・部分指定）+ 解説・つながり、FSRS による復習、段階的な問題解放、IndexedDB への保存、PWA、エクスポート / インポート
- 範囲外: API、ゲーム要素
- 関連 ADR: 0001, 0002, 0003, 0004, 0008
- 完了条件: 自分のスマホで 1 週間続けて使えた

- [ ] 最初の 2 テーマとサブカテゴリを決める（候補: 日本史 > 戦国・安土桃山 / 江戸、絵画 > バロック / 浮世絵）
- [x] フロントエンドの技術構成を決める（ADR-0009）
- [x] 問題データのスキーマを定義する（zod。ADR-0008 のデータ構造、`src/schema.ts`）
- [x] 画面の方向性を決める（統合案 + サブカテゴリ案に決定）
- [ ] モック（サンプルデータ + 全出題形式の画面）でスマホ実機の UX を確認する
- [ ] 問題を生成・検証する Claude Code スキルを作る
- [ ] 2 テーマ分の問題を生成し、レビューする
- [ ] 出題・解答・解説の画面（解説とつながりを表示し、関連する問題へたどれる）
- [ ] 出題形式ごとの UI と採点（択一・並べ替え・組み合わせ・分類・年代推定・地図・部分指定）
- [ ] 地図データ（世界: Natural Earth、日本: 国土数値情報）を簡略化・地域 ID 付与して用意する（国土数値情報の二次利用条件の確認を含む）
- [x] 部分指定のマーカー位置を検証する手順を作る（`pnpm check:markers`）
- [x] 画像の扱いを決める（リポジトリに同梱、ADR-0004）
- [ ] FSRS による復習スケジュール（`ts-fsrs`）
- [ ] サブカテゴリ単位の段階的な問題解放
- [ ] 全体・テーマ・サブカテゴリの達成状況表示と、各範囲からの学習開始
- [ ] IndexedDB への解答ログ保存
- [ ] エクスポート / インポート
- [ ] PWA 化（`navigator.storage.persist()` を含む）
- [ ] 公開先へのデプロイ（Phase 2 に合わせて Cloudflare Workers に配置）

## Phase 2: API と Claude 連携

- 目的: 学習データをもとに、問題の追加・修正のループを回す
- 範囲: Claude 用レポート（手動）→ Cloudflare Workers + D1 の API → 定期実行エージェントによる PR 作成
- 関連 ADR: 0005, 0006
- 完了条件: 定期実行が作った問題追加・修正の PR をスマホからマージできた

- [ ] Claude 用レポートの形式を定義し、コピー / ダウンロード機能を付ける
- [ ] Cloudflare の無料枠の最新値を確認する
- [ ] Workers（静的配信 + Hono API）と D1 を構築する
- [ ] 学習データの送信（学習 1 回ごとにまとめて送信、失敗時は次回再送）
- [ ] 集計と読み取り API（Bearer トークンで保護）
- [ ] 定期実行エージェントを設定する（`/schedule`）
